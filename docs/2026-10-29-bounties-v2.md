# Arc bounties contract, version 2 (29 October 2026)

## Why

The security audit (`docs/2026-10-22-security-audit.md`) left two findings partly fixed, because the
rest of each fix had to be in the contract:
- **#1:** the evaluator key alone could drain the pool. The server caps what bounties reserve in a
  day, but a stolen key does not go through the server.
- **#3:** a rotated-out evaluator still decides the bounties it published, and nobody can stop it
  short of pausing every payment.

## What version 2 adds

`contracts/src/WildsentiaBounties.sol` keeps every version 1 function, event and error. The
server, the explorer links and the watcher read it as before.

**A daily payout cap.**
- At most `dailyPayoutCap` USDC is paid in one UTC day. A payment that would pass it reverts with
  `DailyCapReached`.
- Voids and expiries do not count, since they only return money to the pool.
- The cap starts at ten times the largest bounty. The owner sets it with `setDailyPayoutCap`, never
  below the largest bounty.
- On Arc Testnet it is 10 USDC, as the server's own cap.

**A minimum open time.**
- A bounty can be paid only once it has been open `minOpenSeconds` (`TooEarly` before that).
- That gives the hourly watcher and the owner time to see a publish and pause before money moves.
- It is at most a day. On Arc Testnet it is 10 minutes.

**Revoking one evaluator.**
- `revokeEvaluator(address)` stops that key for good: it can no longer publish, pay or void, and it
  can never be appointed again.
- Its open bounties can be returned to the pool at once with `expire`, by anyone, without waiting for
  them to run out.
- Revoking the current evaluator stops publishing until the owner appoints another.

**Pausing stops publishing too.**
- `setSettlePaused(true)` now refuses `publish` (`Paused`) as well as `settle`.
- `voidBounty` and `expire` stay open, so while paused money can only go back to the pool.
- The function keeps its version 1 name.

## How the server meets it

- **No server change was needed for the new refusals.** A payment refused with `TooEarly` or
  `DailyCapReached` stays in `deciding`, and the pending-decision pass sends it again.
- The gas estimate refuses before any transaction is sent, so a refusal costs nothing.
- A bounty held by the cap until its expiry is returned to the pool.

## Moving to version 2 (testnet, by the owner key)

1. Wait until version 1 has no open bounty in production.
2. Run `npx tsx tools/arc/bountiesV2.ts ~/.wildsentia/arc-testnet-wallets.env deploy`. It deploys
   version 2 with version 1's evaluator and smallest bounty, a largest bounty of 5 USDC (version 1
   allowed 100, above the daily cap), the 10 USDC daily cap and the 10-minute open time, and writes
   the address and block to the file.
3. Run the same command with `move`. It pauses version 1, withdraws its unreserved pool to the owner
   and funds version 2 with it. Run it again for anything version 1 still reserved, once that returns
   to its pool.
4. On Railway, set `VANA_ARC_BOUNTIES_CONTRACT` and `VANA_ARC_BOUNTIES_FROM_BLOCK` to version 2's
   address and block, then redeploy the server.
5. Change `ARC_WATCH_CONTRACT` in `.github/workflows/arc-watch.yml`, and `ARC_BOUNTIES_CONTRACT` in
   the local demo's wallets file.

Version 1 stays on chain, paused and empty. Its past bounties keep their explorer links.
